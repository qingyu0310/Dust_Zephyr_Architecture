# 我的嵌入式进阶学习路线

## 一份不依赖阅读自己代码的长期学习计划

## 1. 路线说明

这份路线是根据我目前已经具备的实践能力定制的。

我已经不再处于“只会点灯、只会调用库函数、只会复制例程”的阶段。接下来真正需要补充的，不是继续堆积更多项目代码，而是把支撑这些项目的底层知识、理论知识和工程方法系统化。

这份路线有三个明确限制：

1. 不把重新阅读自己写过的项目作为主要学习方式；
2. 不把继续设计更多抽象、更多目录和更多宏作为学习目标；
3. 每个阶段都使用独立练习工程、官方示例或其他开源项目完成验证。

学习的核心顺序是：

```text
C/C++ 与内存模型
    ->
Cortex-M 与编译链接
    ->
RTOS 与并发
    ->
Zephyr 外部使用
    ->
通信与驱动
    ->
控制与状态估计
    ->
测试、可观测性与开源工程
```

这条路线不是为了让我马上做出更大的项目，而是为了让我逐渐具备：

```text
能解释底层行为
能预测系统问题
能设计可验证的接口
能把理论写成可靠代码
能维护一个别人可以使用的项目
```

## 4. 学习方式

### 4.1 使用独立练习目录

建议新建一个完全独立的学习目录，例如：

```text
D:\study\embedded-lab\
```

不要直接在当前项目中完成所有练习。

推荐结构：

```text
embedded-lab/
├── c-basics/
├── cpp-memory/
├── cortex-m/
├── rtos/
├── zephyr-samples/
├── protocol-lab/
├── control-lab/
├── test-lab/
└── notes/
```

这样做的目的不是重新造一个大项目，而是让每个知识点都能被单独验证。

### 4.2 每个阶段只保留一个主练习

不要同时开始：

- 一个 RTOS 工程；
- 一个机器人控制项目；
- 一个 Linux 驱动；
- 一个 ROS 项目；
- 一个 FPGA 项目；
- 一个深度学习项目。

每个阶段只保留一个主练习，再配少量阅读材料。

### 4.3 学习必须有输出

每周至少留下以下一种成果：

- 一个可以运行的程序；
- 一张时序图；
- 一份故障分析；
- 一组测试；
- 一份实验数据；
- 一篇简短总结；
- 一个可复现的命令。

不建议只记录：

```text
今天看了多少页
今天看了多少视频
```

更应该记录：

```text
我验证了什么
我观察到了什么
我原来的判断错在哪里
下一步如何复现
```

### 4.4 每个阶段都要有停止条件

如果一个阶段没有停止条件，很容易无限阅读。

每个阶段都需要回答：

```text
什么时候算学会？
什么时候可以进入下一阶段？
哪些内容现在不需要继续深入？
```

- 原子操作；
- 数据竞争；
- 编译单元；
- 符号；
- 链接；
- C++ 对象构造和析构；
- 虚函数表；
- 模板实例化；

### 第一周：C 内存模型

学习内容：

```text
变量存储区域
    ->

    ->
结构体布局
    ->
函数调用栈
    ->
```

练习：

1. 打印不同结构体的 `sizeof` 和成员偏移；
2. 比较数组、指针和二维数组的访问；
3. 手工实现一个定长内存池；
4. 故意制造越界并用调试器定位；
5. 比较栈变量、静态变量和全局变量的地址；
6. 使用 map 文件观察变量最终放在哪里。

### 第二周：C++ 对象模型

学习内容：

- 构造函数和析构函数；
- 拷贝和移动；
- 引用和指针；
- 虚函数；
- 继承的成本；
- 模板和编译期计算；
- `static` 对象；
- 异常和无异常环境；
- `std::array`、`std::span`、`std::optional` 的使用边界。

练习：

- 固定容量数组容器；
- 无动态内存字符串；
- 一个不可拷贝但可移动的资源对象；
- 一个接口类和两个实现类；
- 使用编译器警告检查隐式转换；
- 比较虚函数和函数指针的生成结果。

### 第三周：并发和可见性

学习内容：

- 编译器重排；
- CPU 内存访问顺序；
- `volatile` 能解决什么、不能解决什么；
- 原子变量；
- 临界区；
- 单生产者单消费者队列；
- 多线程共享状态；
- ABA 问题的基本概念。

练习：

- 写一个单生产者单消费者 RingBuffer；
- 用两个线程模拟生产和消费；
- 记录错误读取和丢数据；
- 分别使用普通变量、临界区和原子变量；
- 写一份实验结论，解释三者区别。

### 本阶段交付物

### 推荐材料

## 7. 阶段 2：Cortex-M、启动、异常和编译链接

### 时间

4 周。

### 学习目标

这一阶段要从“会使用 MCU”进入“理解 MCU 启动和运行”。

重点学习：

- 复位后的执行路径；
- 向量表；
- 初始栈指针；
- `.text`、`.rodata`、`.data`、`.bss`；
- 启动文件；
- 链接脚本；
- 中断向量；
- NVIC；
- 异常优先级；
- 临界区；
- HardFault；
- BusFault；
- UsageFault；
- 堆栈回溯；
- DMA；
- Cache；
- 内存屏障。

### 第一周：程序如何启动

练习：

1. 找到一个公开的 Cortex-M 最小工程；
2. 找到向量表；
3. 找到复位入口；
4. 找到数据段复制；
5. 找到 BSS 清零；
6. 找到 `main` 的调用位置；
7. 画出启动流程图。

流程图至少包含：

```text
复位
    ->
向量表
    ->
栈初始化
    ->
数据段初始化
    ->
BSS 清零
    ->
运行库初始化
    ->
main
```

### 第二周：异常和中断

学习：

- 异常进入时硬件保存哪些寄存器；
- 中断优先级如何影响响应；
- 中断嵌套；
- ISR 中为什么不能做长时间阻塞；
- 中断上下文和线程上下文的区别；
- 什么时候需要 PendSV；
- 什么是尾链；
- 什么是中断延迟。

练习：

- 配置两个不同优先级的中断；
- 测量中断响应时间；
- 在 ISR 中设置时间戳；
- 让低优先级任务被高优先级中断打断；
- 故意在 ISR 中做错误操作并记录结果。

### 第三周：Fault 调试

练习：

1. 制造空指针访问；
2. 制造非对齐访问；
3. 制造栈溢出；
4. 制造非法指令或错误函数地址；
5. 记录 Fault 状态寄存器；
6. 使用 GDB 还原调用栈；
7. 写一份 Fault 诊断模板。

Fault 诊断模板：

```text
异常类型：

PC：

LR：

SP：

异常状态寄存器：

当前线程：

调用栈：

可能原因：

复现方式：

修复结果：
```

### 第四周：链接、DMA 和 Cache

学习：

- 链接脚本段；
- section 放置；
- 自定义 section；
- `KEEP()`；
- 编译器优化；
- DMA 缓冲区；
- Cache clean；
- Cache invalidate；
- DMA 与 CPU 的一致性。

练习：

- 把一个变量放到自定义 section；
- 在 map 文件中找到它；
- 比较启用和禁用优化后的地址与符号；
- 做一次 DMA 接收实验；
- 在有 Cache 的内核上验证缓存一致性问题；
- 写出 DMA 缓冲区使用规则。

### 本阶段交付物

```text
cortex-m/
├── startup-notes.md
├── interrupt-latency/
├── fault-demo/
├── linker-section/
├── dma-cache/

```

### 通过标准

能够解释：

- 程序复位后第一条指令从哪里来；
- 为什么某个函数被链接器删除；
- 为什么自定义 section 需要链接脚本保留；

## 17. 现在暂时不要投入太多时间的方向

### 17.1 不要继续无限扩展抽象

现在不需要把每一个小功能都抽象成平台。

学习阶段应优先问：

```text
这个抽象能不能被测试？
这个抽象是否解决了实际问题？
这个抽象是否有清晰的所有权？
```

### 17.2 不要同时学习多个 RTOS

优先把一个 RTOS 学深。

等到能够解释：

- 调度；
- 同步；
- 线程栈；
- 中断；
- 内存；
- 定时器；

之后，再对比 FreeRTOS、RT-Thread 或其他系统。

### 17.3 不要过早进入大型生态

暂时不建议把主要精力转移到：

- ROS；
- 大型 Linux 驱动；
- FPGA 全流程；
- 深度学习部署；
- 多种机器人中间件；
- 大型前端工具链。

这些方向以后都可以学，但当前最值得补的是 MCU、RTOS、控制和测试的基础深度。

### 17.4 不要把视频观看当成学习完成

看完课程不等于掌握。

至少要完成：

```text
一个最小实现
一个异常实验
一组测试
一份总结
```

## 18. 外部资料选择原则

### 18.1 第一优先级：官方文档

优先顺序：

```text
芯片官方 Reference Manual
Arm 官方架构文档
Zephyr 官方文档
CMake 官方文档
Python 官方文档
```

### 18.2 第二优先级：经典教材

推荐：

- 《C Programming Language》
- 《Effective Modern C++》
- 《Computer Systems: A Programmer's Perspective》
- 《Operating Systems: Three Easy Pieces》
- 《Feedback Systems》
- 《Probabilistic Robotics》

不需要全部买齐。

每个阶段只选一本主教材。

### 18.3 第三优先级：论文和源码

当基础概念已经可以解释后，再阅读：

- Kalman 原始论文；
- EKF 相关论文；
- 电机辨识论文；
- RTOS 调度论文；
- 优秀开源驱动；
- 优秀测试框架。

不要一开始就从论文开始。

### 18.4 中文资料的使用方式

中文资料适合：

- 快速建立概念；
- 了解工具使用；
- 对照术语；
- 获取实践经验。

遇到以下内容时，最终应回到英文官方资料：

- 寄存器；
- 异常模型；
- 编译器；
- 链接脚本；
- RTOS 内核；
- USB；
- CAN；
- Cache；
- 控制算法推导。

## 19. 最终能力目标

完成这条路线后，希望达到以下状态。

### 底层

能够从启动文件、向量表、链接脚本和 Fault 寄存器定位 MCU 问题。

### 并发

能够判断一个数据应该使用：

```text
普通变量
临界区
原子变量
互斥锁
消息队列
快照
```

而不是凭习惯选择。

### 通信

能够设计一个允许：

```text
半帧
粘包
丢帧
错误校验
超时
恢复
```

的通信协议。

### 控制

能够从采样、延迟、噪声和模型角度解释控制效果。

### 测试

能够让错误输入自动暴露，而不是等上板后偶然发现。

### 工程

能够把一个小型 C/C++ 库做成：

```text
可构建
可测试
可复现
可发布
可维护
```

### 表达

能够把一个复杂问题讲清楚：

```text
问题是什么
为什么发生
怎么验证
怎么修复
还有什么限制
```

## 20. 最后给自己的提醒

我现在不需要继续证明自己“能不能写出东西”。

我需要做的是把已经拥有的实践能力，转换成稳定的理论能力。

不要因为新的知识暂时看不懂，就否定过去做出来的东西。

也不要因为过去能写出东西，就跳过底层原理。

接下来最重要的不是追求更大的项目，而是完成一个又一个独立、可验证、能解释的实验：

```text
一个内存实验
一个异常实验
一个调度实验
一个协议实验
一个控制实验
一个测试工程
一个可发布的库
```

最终希望达到的不是“我还能不能写出更多代码”，而是：

> 我能够理解系统为什么这样运行，也能够用可靠的方法把它做对、测出来，并交给别人使用。
